# Public QK norm / RoPE / gate-copy contract audit

## Finding
The explicit Qwen3NextAttention fused helper is **not selected by compilation/graph mode**. In installed public `qwen3_next.py:373–393`, selection requires output gating, NeoX-style RoPE, CUDA or XPU, FP16/BF16 rotary dtype, and text-only or supported interleaved MRoPE. `_project_qkv_gate:407–434` invokes the Python-imported `fused_qk_rmsnorm_rope_gate` when that Boolean is true. Thus `enforce_eager=True` or Inductor `enable_qk_norm_rope_fusion=False` does not establish that this explicit helper is off. The latter setting is a different fusion mechanism. Current eager helper selection has not yet been recorded directly.

## Observed evidence versus source expectation
- Original optimized trace inventory K025 records `_fused_qk_rmsnorm_rope_gate_kernel` 768 times across six complete requests: 128/request. Grid (1696,20,1) appears 48 times; (32,20,1) appears 720 times, all720 graph-node events. Blocks are (128,1,1). Layer/phase interpretation comes from public source; kernel records do not contain API operands.
- Existing `packedCapture01` directly saved layer3 `self_attn.qkv_proj` output at prefill [1696,10240] and decode [32,10240], BF16, stride[10240,1], offset0, stream0. Therefore these saved projection tensors are concrete actual inputs to the public split, not merely shape guesses.
- Public split maps q_gate columns0:8192, k8192:9216, v9216:10240; within each Q head, query256 then gate256. Q_gate/K helper-view strides and offsets are source-derived from the saved contiguous output, not directly recorded helper descriptors.
- The attention-gate capture wraps `_project_qkv_gate` and preserves its original tuple. It captures only the returned gate, attention output and projection consumer. It does **not** record `use_fused_qk_norm_rope_gate`, Q/K weights, positions, cos/sin cache or fused helper dispatch. Existing successful gate/norm ports do not qualify this fused function.

## Functional contract from public Apache-2.0 source
`fused_qk_norm_rope.py:138–276` accepts q_gate[M,2*Hq*D], K[M,Hkv*D], per-head weight vectors[D], packed cos/sin cache[max_position,rotary_dim], positions[M] or[3,M], epsilon, head counts, head/rotary dimensions, optional MRoPE sections and norm_beta. FP16/BF16 Q/K must match; last tensor dimensions must be contiguous. Row strides and position strides are passed explicitly. Positions are converted to int64 before address calculation. For 2-D positions, sections sum to rotary_dim/2; H/W frequencies are selected with modulo3 and strict `< 3*section` masks; the other frequencies use T.

Qwen source parameters at TP1: Hq16/Hkv4/D256, rotary64, epsilon1e-6, norm_beta1.0, interleaved sections[11,11,10]. These derive from pinned model/source and are not a substitute for an actual helper snapshot.

For each token/head, the kernel loads X in FP32, reduces X*X over the full256 head, divides by256, adds epsilon and uses reciprocal sqrt. Weight is converted to FP32 then norm_beta is added. **Normalized X is explicitly rounded to input BF16/FP16 and converted back to FP32 before RoPE.** Tail64:256 is normalized-only. The first64 values are NeoX pairs (i,i+32) with output `(x1*cos-x2*sin, x2*cos+x1*sin)`, stored to input dtype. Gate is copied verbatim, not sigmoid-applied. Input Q/K/weights/cache/positions are read-only. Three separately allocated contiguous outputs are returned: Q[M,4096], K[M,1024], gate[M,4096]; V is not passed to this helper and remains the original projection view in the caller. Zero tokens return freshly allocated empty outputs without launch.

FP32 reduction association, mul/add contraction in norm/RoPE, reciprocal-sqrt behavior and cache values are material to raw comparison. Mathematical equality does not prove raw equality. Source specifies `num_warps=max(1,next_power_of_2(D)//64)=4`, two stages and grid(M,20), consistent with observed geometry. The separate gated-norm N128/warp1 reduction fix must not be reused blindly here. Cache construction normally casts to rotary dtype (base.py59–63), but actual dtype/value/stride and any later replacement remain unobserved.
