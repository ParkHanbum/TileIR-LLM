Transparency / evidence availability

A recipe is not
a replayable artifact.

Publication limit: this site currently publishes verified summaries and measurement contracts. It does not yet include the complete pinned binaries, prompt-ID fixture, manifests or per-request raw timings needed to reproduce every result. Do not treat the summary CSV as raw data. Local experiment identifiers may not yet be available on the public remote.

Reproduction checklist

  1. Pin the model repository and exact revision; record checkpoint index/shard and tokenizer hashes. Obtain weights through their original distribution and license, not this site.
  2. Publish the exact input-ID fixture, dimensions and generation policy. B32/P53/G16 alone is insufficient.
  3. Record GPU model, Driver/CUDA/toolchain versions, runtime versions, executable/build flags and CUBIN/ABI manifests.
  4. Pin both engine configurations, including effective graph/compile mode, prefix caching, precision, outputs and memory budgets.
  5. Qualify positive and negative cases before the benchmark. Preserve crash/failure handling and ownership constraints.
  6. Run serial blocks with an exclusive benchmark lock and fresh memory admission. Warm resident engines, reset independent request state, and exclude reference comparison/logging from the timer.
  7. Save all per-request times, tokens, block order, warmup flags, exits, cleanup and recovery receipts. Report distributions and limitations.

Evidence currently summarized

Recorded report groups are native-sixteen-token-9f9863a-01, native-warm-paired-01, and native-guard-batch-01. Names identify the underlying experiments; they are not download links. Summary rows on this site can be downloaded in CSV and JSON.

Minimum public evidence bundle for each future entry

entry.md               question, change, result, limits
manifest.json          source/build/config/input identities
commands.txt           actual tested invocation (redacted as needed)
requests.csv           raw per-request measurements + warmup flag
correctness.json       expected/actual comparison and scope
process-outcomes.json  actual exits, retries, recovery
checksums.sha256       evidence-file integrity

Publish only sanitized project artifacts. Do not publish credentials, private paths, environment dumps, personal prompts, checkpoint weights or third-party binaries without redistribution rights. Commands should come from tested manifests, not guesses.

How to maintain this site

Static HTML/CSS with relative URLs; no build service, JavaScript dependency or external font required. Add a dated entry and update the ledger and summary data together. Use the template. Keep corrected historical entries with a correction note rather than silently merging experiments.

The project repository is the intended home. GitHub Pages deployment configuration is maintained separately from the site content.
