## Before/after logical flow
TileIR B:
BF16 hidden[B32,T53,2560] → four projections(qkv,z,b,a) → qkv transpose[B,8192,T] → update conv cache →32 per-row left-pad3 + depthwise conv width4+SiLU → concat → split/reshape q,k[B,T,16,128],v[B,T,32,128] → beta/g gate → physically repeat q/k heads16→32 → typed contiguous input ports → per-chunk FP32 g cumsum → intra(normalize q/k; QK/beta/decay; serial triangular solve; WY-like corrected V and K) → combined inter(correction,causal QK/output,state update) → crop64→53,transpose,contiguous,castBF16 → update recurrent cache → gated RMSNorm with z → output projection to2560.

vLLM:
BF16 packed hidden[L1696,2560] → merged qkvz and merged ba projections → views qkv/z/b/a → packed variable-length depthwise conv width4+SiLU, update indexed conv cache → fused split+q/k normalization+beta/g → q/k keep16 heads;v32 heads → g cumsum → KKT → block triangular inverse → WY w/u → h recurrence+v_new → separate output o → scatter final state to indexed cache → gated RMSNorm with z → output projection2560.

Same high-level Gated Delta Rule, but different arithmetic boundary, layout, cast and cache contracts. Neither flow is only BLAS.

## Stage contracts and important differences
1. Projections (BLAS): B logical M1696,K2560, N8192(qkv),4096(z),32(b),32(a), no bias. vLLM public merged weights imply N12288(qkvz) and64(ba), same M/K and split order [q,k,v,z],[b,a]. These vLLM GEMM shape values are source/config inference, not a direct cuBLAS API argument capture. Output projection logical M1696,K4096,N2560. Need specify BF16 input/output, accumulation/compute mode, transposed weight storage, alpha=1/beta=0 where confirmed by the actual API record; do not infer API flags solely from nn.Linear.

2. Conv/cache (non-BLAS): B qkv[B,8192,53] is transposed from projection. Per row pads3 zeros, then FP32 four-tap products+SiLU and BF16 store. Weight[8192,4]; no bias in this model path. Static B conv cache keeps last4 positions[B,8192,4]. vLLM packed sequence boundaries come from query_start_loc; source documents conv state trailing width−1 and indexed sequence slots, possibly transposed according to DS/SD layout. Exact runtime cache stride/layout option needs descriptor capture; numerical sequence boundary equivalence is not implied by identical allocation shapes. B physical zero padding is not cross-sequence padding; vLLM must not mix adjacent packed requests.

3. Gates (non-BLAS): beta=sigmoid(b),g=−exp(A_log)*softplus(a+dt_bias). Both calculate in FP32. B stores beta in b.dtype(BF16), gFP32. vLLM stores both beta and gFP32. B softplus source uses log(1+exp(x)); vLLM uses sign-stable formulation plus threshold20. B sigmoid uses1/(1+exp(−b)); vLLM tl.sigmoid. Functional real-number formulas agree; finite precision, large-magnitude and nonfinite behavior can differ.

4. Q/K normalization/head mapping (non-BLAS): B physically repeats each key head twice to H32, then intra computes FP32 rsqrt(sum(x²)+1e−6). vLLM retains Hk16, computes FP32 1/sqrt(sum(x²)+1e−6) in fused_post_conv, stores normalized BF16, and maps value head hv to key head hv//2 later. B scales Q by1/sqrt(128) before BF16 intermediate store; vLLM output kernel applies scale after dot expressions. The store/cast/scaling placement is a genuine rounding-contract difference.

5. Chunk layout/padding (non-BLAS): both CS64 and53 live tokens. B materializes Q_ch,K_ch,V_corr,K_cumdecay[B32,H32,1,64,128] BF16, with zero-padded input loads. Contiguous allocation-derived element strides are(262144,8192,8192,128,1), not a captured runtime pointer tuple. G_cum[B32,H32,1,64] isFP32. B output scratch uses the same5D shape inFP32. Its g scan after live token52 is flat because padded g=0, so g_last at63 equals live end in finite arithmetic. vLLM packs L1696 with cu_seqlens length33, allocates q/k[1,L,16,128],v[1,L,32,128],g/beta[1,L,32]; q/k/v contiguous BF16, g/betaFP32. Source-derived strides of inner q/k are(2048,128,1), v(4096,128,1). Varlen masks stop each sequence at53, no allocation of a B×64 full output; scratch A has64 columns. Exact actual strides remain uncaptured.

6. KKT/triangular solve/WY (mixed matmul + non-BLAS): B intra forms beta*K inFP32; _ct_mm castsFP32 operands toTF32 before ct.matmul/FP32 result. It builds strict lower A=−beta_i*(k_i·k_j)*exp(G_i−G_j). With normalized keys, serial64-row reference-order solve is mandatory in current B. It forms corrected V=Ainv*(beta*V) and decayed K=Ainv*(beta*K*expG), then BF16 stores. vLLM separates KKT,16×16-to64×64 inverse merge and WY. A KKT output isFP32, solved A is cast to k.dtype(BF16); WY beta-weighted operands are castBF16 before dot; w/u storeBF16. A generic GEMM API cannot describe the triangular masking, recurrence-order solve or these cast boundaries without auxiliary contracts. No claim of raw equivalence between solvers.

7. Recurrence/output (matmul plus non-BLAS): B state isFP32[B,H,K,V], row-major K-major/V-contiguous. It computes Vnew=Vcorr−Kcum*state; inter Q-weighted*state; causal(QK*decay)*Vnew; state=state*expGlast+(K*exp(Glast−G))ᵀ*Vnew. Combined inter performs output and state. All _ct_mm calls useTF32 casts/FP32 accumulation. B writes padded FP32 output then castsBF16 through product output port. vLLM state isFP32[N,H,V,K], V-major/K-contiguous: transpose relative to B. It uses64-wide K blocks for h, BF16-casts h operands for dot, stores per-chunk h in k.dtype(BF16) and v_new in u.dtype, then separate o kernel. vLLM h alone is not equivalent in work to B inter: h+o at least must be considered. The value-head grouping mapping is implicit in vLLM, explicit repeated data in B.

8. Cache/output (non-BLAS + final BLAS): B initial prefill state=None, allocates final[B32,32,128,128]FP32 and copies into stable cache. vLLM gathers indexed state slots and zero-masks requests without initial state, returns final[N32,32,V128,K128]FP32 and indexed-scatter stores. Equal K/V sizes hide the axis-order difference, so shape equality alone is unsafe. B converts output layout/casts via `_operand_capture.output` in active product_chunk_merged_v1, not bare original forward. Both apply RMSNorm then SiLU(z) gating (epsilon1e−6), BF16 outward data and output projection. Exact compiler-fused normalization rounding also needs cross-runtime capture.

## TileIRBLAS vs auxiliary API boundary
BLAS: dense projection GEMM with precise layout/compute/epilogue contract; grouped/strided-batched small matmuls with specified K-reduction and output dtype; GEMM-based WY products. No automatic claim that every in-kernel ct.matmul is an external cuBLAS call.
Auxiliary: packed-sequence metadata; causal depthwise conv/cache update; stable sigmoid/softplus/log-decay; q/k L2norm with epsilon/cast policy; head mapping/repeat; chunk scan/padding/masks; triangular solve/inverse with operation-order policy; gated recurrent state/layout transform; output cast/transpose; gated RMSNorm; indexed gather/scatter/static cache ownership. These must be independently specified even if fused into fewer TileIR kernels.
A useful contract records axes and units, shape/stride/storage offset, input/output/accumulation dtype, head grouping, sequence boundaries, zero/initial-state meaning, transpose conventions, alpha/beta/epilogue, alias rules, mutation/output ownership, finite/nonfinite handling, and allowed numerical error. Preserve raw-bit equality as a separate result, not the definition of functional equivalence.

## Verified vs missing
Verified in existing runs: same32×16 generated token IDs across matched runtimes; B/N81 raw model output/cache comparison; P variants raw match B on this workload. These are NOT vLLM intermediate raw-equivalence proofs. The81 gate compares TileGym-family arms, not aligned/transposed vLLM state/cache.
Missing: cross-runtime capture immediately after projection, conv, gates, normalization, KKT/solve/WY, h/o and final state; exact vLLM API descriptors, memory strides, selected parameter dtypes, and intermediate error envelopes. Source already shows beta precision, normalization/scaling placement, solver precision and state transpose differences, so a staged comparison must align semantics/layout before assessing any discrepancy. Output token equality alone can hide logit/state differences.
No new runtime test is proposed or executed in this report. Optimization candidates remain stopped and preserved.
