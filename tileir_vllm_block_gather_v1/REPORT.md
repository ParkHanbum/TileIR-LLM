# Public block-table gather companion, CPU preparation only

Selected independent call: GPUModelRunner.prepare_attn -> BlockTables.gather_block_tables -> public Triton _gather_block_tables_kernel. Existing optimized six-request inventory K040 records 96 events, 16/request, grid [4,32,1], block [128,1,1], graph_node_count=0. This supports a four-group / 32-row launch interpretation given this source, not actual tensor-pointer/dtype/value capture. Eager pointer API and optimized occurrence identity are not automatically identical. No saved block-table bank found in project filename scan.

## Narrow callable
`gather_block_tables(src_tuple, counts, indices, out_tuple, padded)` mutates output and returns prefix views retaining output storage. Counts int32 [groups, request_capacity]; source/output int32 row-major matrices, group-specific capacities allowed. Index int32 or int64 vector; actual placement/dtype must be captured, not inferred. All tensors contiguous on the same CUDA-visible device. Actual rows copy only counts[g,req] columns, leaving the remaining tail untouched. Padded rows are fully zeroed; rows >= padded unchanged. Source, indices and counts unchanged. No allocation, copy, implicit synchronization, vendor fallback or output buffer recycling; current stream. Entire output backing intervals must be disjoint from every input and other output, including distinct Storage wrappers. This is stricter than public vLLM's unchecked raw-pointer boundary.

Value preconditions are request indices in [0,capacity), counts for used requests in [0,width]. In particular, -1 dummy indices are NOT supported by the original gather (unlike the neighboring slot-mapping operation). Metadata is validated before launches; device values are not host-read inside the API. `validate_values_cpu` checks captured values before qualification; this is not runtime value validation. Empty group tuples are currently unsupported, though vLLM handles them. Multi-group launch fusion, arbitrary strides, autograd, pointer-array ABI registration and PCP orchestration are not implemented.

## Placement / lifetime
BlockTables sources normally StagedWriteTensor CUDA allocations; counts is UvaBackedTensor.gpu. Public buffer_utils.py uses get_accelerator_view_from_cpu_tensor for mapped pinned CPU storage when UVA available, and a copied device-buffer fallback otherwise. Therefore `.device == cuda` alone does NOT establish device-resident memory. This facade accepts CUDA-visible metadata but mapped-UVA access through cuTile remains UNQUALIFIED. Capture must record actual placement provenance and preserve the backing owner's lifetime. Do not silently move counts to device and claim identical boundary. Source/outputs must remain live and unmodified until current-stream completion.

## Prepared implementation, not GPU-tested
One TileIR launch per group, grid (padded,ceil(width/256),1). Each actual-row valid prefix writes once, masked beyond count/width; padded rows zero. No reduction or FP arithmetic. Integer equality is the required comparison, not a changed floating-point tolerance. `kernels.py` is AST-checked only; no CUDA initialization, compile or launch done. Seven CPU tests pass for int32/int64 indices, heterogeneous widths, zero count, preserved tails and unused rows, output view alias, invalid values, metadata failure, cross-storage overlap and no CUDA initialization. CPU semantics are not proof of CUDA correctness.

## Minimal actual-input qualification plan
Reuse the existing approved eager native-vLLM capture runner; install an explicit wrapper only around one selected prefill and one selected decode `prepare_attn` gather, after warmup. `capture.capture_call` is a prepared opt-in adapter, not installed or executed: caller supplies original bound method and phase label; exactly one native call, snapshots before/after, hashes, error progress, and unused output directory. It supports default output buffers only. It captures full output capacities so tail/padding/unused-row preservation can be checked, as well as all source groups/counts/idx metadata. Snapshot transfer synchronizes and is diagnostic-only. Phase label must come from the runner, not call order guessing.

Then CPU-check indices/count bounds; reconstruct actual strides and offsets; replay public original and TileIR from identical before buffers using distinct output backing, compare all int32 bits, all prefix views and all input bytes. Preserve at least one actual mapped-UVA test if that is the native placement; device-only copies are a separately labeled arm. Add synthetic zero-count, padded, boundary capacity and duplicate-index tests. Raw mismatch is HOLD, no tolerance relaxation. Parent coordinates bounded GPU admission/cleanup separately. No timing/performance or functional coverage claim yet.
