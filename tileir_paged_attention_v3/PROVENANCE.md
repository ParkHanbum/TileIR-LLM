One targeted delta from v2: BF16 Q/K inputs now enter public ct.mma with FP32 accumulator rather than FP32 elementwise multiply and tree sum. Public release-pinned FA2 flash_fwd_kernel.h gemm(acc_s,...) and kernel_traits.h BF16 MMA types motivate this change. A query is broadcast to16 identical rows, MMA produces16x128 scores and first row alone is used. This retains old one-query grid,128-column softmax/PV reduction and masks; no performance claim. Compiler MMA instruction/accumulation order is not yet validated and not claimed identical to FA2. BF16 unnormalized exp rounding, current exp association, FP32 denominator, elementwise PV and final division unchanged. This also avoids changing key reduction width while probing QK. Actual first two banks lengths53/54 are validation scope;65–68 remain unvalidated even though API guards accept them.
