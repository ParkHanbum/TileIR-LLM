# Indexed ordinary prefill convolution, public-source candidate
Functional TileIR adapter, not full cuBLAS/vLLM ABI. Actual workload BF16 X[8192,1696] channel-last view, W[8192,4], state[capacity,8192,3] with nonoverlapping DS strides, int32 query boundaries0..1696 step53 and unique positive indices32, bool initial flags allFalse. No bias, SiLU, no pad/null, no APC/speculation/initial history use/other lengths/backward. Rejects unsupported metadata before launch. CPU metadata synchronization is explicit; no performance claim.

Fresh output[8192,1696] stride[1,8192], no input alias. X/W/query/index/flags unchanged. Selected indexed history becomes final3 original X tokens; other logical state and minspan holes unchanged. The actual state is a view within a larger shared owner; isolated replay reproduces exact logical strides/offset and minimum backing span, not unrelated original owner values.

Public installed vLLM0.32 causal_conv1d.py Apache-2.0, copyright contributors to vLLM; original interface Copyright(c)2024 Tri Dao, adapted from Dao-AILab/causal-conv1d. Separate prefill public generated TTGIR FKECCMTL... lines329-350 shows BF16 tap product then FP32 expansion/ordered sum, and PTX lines554-605 BF16 fma(-0), f32 additions, ex2.approx, div.full. This is not a driver loaded-address binding claim. Candidate explicitly rounds each product BF16 after FP32 multiplication, then sequential RN FP32 sums and SiLU FULL division. Finite captured-bank equivalence needs GPU validation; no arbitrary underflow/overflow/NaN equivalence is asserted.

Metadata.nums_dict/batch_ptr/token_chunk_offset_ptr affect native work scheduling and are restored for native replay. Narrow TileIR adapter validates actual mathematical sequence partition directly and does not pretend to expose or consume those native scheduling structures.
