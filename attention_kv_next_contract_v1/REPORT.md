# Next attention/KV functional boundary: native KV scatter capture first

CPU public-source review only, no backend imports, GPU query/init/lock/compile or source modification. Current Qwen3.5-4B target is BF16 TP1 eager B32/P53/G16. Existing attention sigmoid/QK-RoPE/slot mapping ports do not qualify paged KV writes or attention softmax.

## First target and exact dispatch limits
Choose paged KV insertion (`reshape_and_cache_flash`) before whole attention core. It has a narrower data-movement contract than fused masked softmax, and ordinary nonquantized BF16 insertion should preserve bits rather than introduce new floating point reduction. This is a proposed first target, not yet a qualified API.

Public Attention.unified_kv_cache_update resolves actual layer/kv_cache/slot_mapping, calls impl.do_kv_cache_update only when mapping exists, then returns an empty dummy tensor for graph side-effect ordering. This dummy is NOT the reshape helper return. Public FlashAttentionImpl.do_kv_cache_update returns None; encoder paths skip cache updates. It derives key/value cache views via kv_cache.transpose(1,2).split(head_size,-1) and calls its imported reshape_and_cache_flash. On CUDA, fa_utils imports the public vllm._custom_ops wrapper, which calls torch.ops._C_cache_ops.reshape_and_cache_flash and returns None. Do not patch or replace the attention dummy-producing outer boundary accidentally.

Backend class/helper selection must be observed live. No claim that the earlier optimized trace proves this exact eager backend. A different backend, helper, quantized cache, unsupported layout or missing slot map must be captured as descriptors/HOLD, not forced to FlashAttention.

## Storage and slot contract
FlashAttention source documents cache [blocks,KVheads,blocksize,2*headsize]. Derived K/V views are [blocks,blocksize,KVheads,headsize] with shared backing and disjoint logical channel halves. Their allocation spans overlap; simplistic whole-storage overlap rejection would incorrectly reject the intended aliases. Neither persistent view can be cloned wholesale from storage_nbytes, since backing may include multiple layers/padding.

Expected logical K/V are [M,4,256], M1696 prefill or32 decode, but exact runtime descriptors remain unobserved. Padded K/V row counts can exceed slot_mapping length; the latter controls live token count. Slot/blocksize gives block and position. Installed public Triton alternative explicitly skips negative slots; positive duplicate slots can race, so reject duplicates for first independent replay. Its native-cache path copies values without scale arithmetic. This alternative is public design evidence ONLY, not proof of the CUDA custom-op selected implementation. Before claiming negative-slot or arbitrary-layout parity, bind official C++ public source version or experimentally qualify those cases; fixed eager workload may not exercise negatives at all. Quantized FP8/cache scale behavior is excluded from first port.

## Small exact-once capture plan
Use the successful native-only engine/launcher lifecycle, one unobserved request followed by one observed request, fixed512 token IDs, no timing claims. Public apply_model enumerates eight actual attention modules and records class, impl/backend, do_kv_cache_update identity, kv dtype/scales and cache descriptors. Install a scoped wrapper on the actual impl method and (only when its public source binding is identified) its imported reshape helper. Preserve original callable count1, arguments, exact return object/None; restore bindings on success/failure. Nested owner context associates helper arguments with the exact layer and request step. Record original stream and distinguish it from vendor internal stream proof.

Count all8 layers x16 forwarded batches=128 expected updates; phase from live attention metadata/runner batch evidence, never only M. Capture first layer3 prefill and first decode only. Save K/V and slot mapping before/after plus scale logical values, dtype/stride/offset/type/grad and owner/helper identities. Record full persistent cache descriptors but NEVER snapshot its whole backing. Copy only unique addressed K/V slots before/after using bounded canonical selections; retain original slot order and token-to-slot mapping. Hard bound selected snapshots (e.g.64MiB per tensor, total256MiB) checked before transfer. Input K/V/slots/scales should be hashed unchanged. Invalid/out-of-range/duplicate slot observations fail before selection or remain unsupported diagnostic evidence.

Selected-slot snapshot proves written values/aliases for those slots only, NOT untouched-slot/page-padding preservation. A later standalone replay should reconstruct a compact caller-owned cache with original strides and sentinel values, compare targeted writes raw, returnNone, input preservation and all untouched compact storage. Whole engine shared-cache preservation would require separately bounded streaming checks, not an unbounded5GiB clone. Cache overwrite correctness and attention output correctness remain separate gates.
