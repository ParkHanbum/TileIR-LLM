# Narrow public post-conv TileIR v2 candidate, whole-function qualification pending
Public vLLM contributors, Apache-2.0. Derived only from public fused_gdn_prefill_post_conv.py and its locally generated public Triton IR. No vendor disassembly. This is a fresh-output functional API, not binary ABI. Same positional/keyword defaults for H16,K/V128,apply_l2norm=True,output_g_exp=False; only observed L1696 contiguous offset0 BF16 conv/a/b/dt and FP32 A_log. No decode, empty, noncontiguous, gradients, alternate options or arbitrary shape support. Validation precedes allocations/launch. Input-input alias is allowed (read-only); output allocations are fresh.

Source TTGIR shows lane16 each8 contiguous values, LLVM has sequential local sum then butterfly8,4,2,1; explicit RN expression preserves this proposed tree. Public wrapper scalar math uses sqrt then div.full, not rsqrt. Candidate beta stays FP32, V copy and Q/K BF16 rounding preserved. Cache has multiple specializations, not a loaded-instance proof. Candidate log/exp/sqrt lowering, possible compiler contraction and final raw equality remain experimentally unproven. Replay must HOLD on any raw/finite mismatch; strict1e-5+1e-5|ref| is separate diagnostic, not relaxed adoption. No performance claim.

V2 delta: sqrt explicitly uses RM.APPROX and flush_to_zero=True to match the observed public native PTX option. Q-only stage evidence is in gdn_post_conv_q_diagnostic_v1/RESULT-REPORT-01.md; this does not by itself qualify the full uninstrumented API.
