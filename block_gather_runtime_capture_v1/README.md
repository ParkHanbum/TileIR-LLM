# Block-table gather native capture, CPU-ready only

Reuses attention_gate_runtime_capture_v1 run.py and launch.py lifecycle unchanged except description/scope. Same local Qwen3.5-4B revision, B32/P53/G16 BF16 eager native vLLM, async scheduling, compilation+graphs disabled, one warmup and one captured request. Every request must reproduce frozen native 32x16 (512) token IDs. No performance claim. Parent admission/common lock/900-second child/930-second parent/owned group cleanup/post-admission remain unchanged. No cache preseed copied and no executable invocation performed here.

Observer attaches via engine.apply_model but observes public GPUModelRunner.prepare_attn and its exact runner.block_tables.gather_block_tables call. Batch.is_prefilling_np, has_prefill, num_computed(_prefill)_tokens, prefill lengths, query starts, scheduling counts, request IDs and padding sizes define phase. M1696/32 is not a phase heuristic. Only the first all-prefill and first all-decode boundary is captured; mixed or repeated phases pass unchanged. PCP is explicitly unsupported and fails closed. Selected default-output native gather called exactly once; its tuple object is returned verbatim. Outer prepare_attn return is also unchanged. Class patches are restored, refusing to overwrite foreign bindings.

All logical inputs, all persistent output capacities before/after and prefix return tensors are saved, each with original dtype/device/stride/storage-offset/pointers/backing byte count. Each record also saves the ENTIRE backing allocation as uint8, not just logical values, including unused capacity/tails. Preserves pre/post input backing equality; actual output mutation is retained, not restored. No TileIR substitution occurs. All artifacts hashed. PROGRESS is mutable failure evidence; final MANIFEST created with exclusive write and linked by SHA to the result.

Counts provenance records UvaBackedTensor.cpu source, active pool buffer CPU storage, active accelerator view and counts GPU view before/after, including pinned status, device/ptr/storage alias and buffer class. Public UvaBuffer uses a mapped CPU accelerator view while NonUvaBuffer uses explicit-copy device fallback. No `.device`-only physical-memory inference. Full snapshots synchronize and may affect execution timing, so this is diagnostic-only. Active views and owner references remain live throughout the original call.

CPU tests: six pass, including exactly-once/return identity, preserved untouched output row, phase independent of M, snapshot failure cleanup, conflicting binding refusal, complete storage capture from offset views and no CUDA initialization. Kernels not imported/compiled. No actual bank exists yet; actual placement, class-hook boundary reachability, complete two-phase capture and native token identity remain GPU qualification gates. Runtime launch requires parent coordination and final independent review.

This is a new folder; original attention capture and block-gather API sources are unchanged. Reused source hashes and public vLLM source hashes are in PINS.json. Public source only; no proprietary binary analysis.
