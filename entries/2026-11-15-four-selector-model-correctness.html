2026-11-15 / native model correctness · selector composition

Four selectors, one native model.
Check composition before timing.

A fixed BF16 Qwen3.5-4B fixture completed the ordered native execution sequence 0000 → 1100 → 1111. The recorded checks retain exact generated IDs and Down hashes across these three configurations. This is a correctness qualification, not a speed comparison; the independent saved-evidence audit passed.

No vLLM execution or matched performance measurement took place in this group. The historical 8.43× matched request checkpoint is unchanged and is not a ratio for this combined implementation.

What the four bits select

bit order: P D G Q
P = prefill Gate specialization
D = decode Down specialization
G = decode Gate specialization
Q = prefill QKVZ specialization

0000  baseline routes
  ↓
1100  P + D selected
  ↓
1111  P + D + G + Q selected

A single pinned native C++ engine binary was used throughout (public-friendly short identities: d84f0213 / 36098892). The workload was BF16 Qwen3.5-4B on an RTX 4080, batch 32, prompt length 53, 16 generated tokens per row, greedy decoding. The comparison changes the four selectors, not the engine binary or the fixed input fixture.

Execution and admission sequence

The three model executions ran in the order above, with two CPU inspection steps. Five fresh censuses used the same base; inactive routes remained checked rather than disappearing from admission coverage. Every model execution, both CPU inspections, the launcher and the independent recovery returned actual exit code 0.

What was checked

  • Per arm: 512 raw self-generated token IDs and 512 Down hashes matched exactly.
  • Recorded stage coverage: 96 P records, 1,440 G records and 48 Q records per arm.
  • G weight checks cover 64 endpoints; Q weight checks use the strict W contract.
  • Fresh same-base census and inactive-route checks accompany the selected-route counts.

Exact tokens mean equality of the recorded generated IDs for this fixed fixture, not proof of model equivalence for arbitrary prompts. Stage records and hashes are not independently archived full raw tensor outputs. Endpoint or strict checks do not prove that every possible transient weight mutation followed by restoration would be detected.

How to reproduce the comparison responsibly

  1. Pin one native C++ binary, the same model weights, fixed tokenized input fixture and BF16 greedy B32/P53/G16 settings.
  2. Keep all non-selector settings identical. Regenerate the same-base censuses, including routes disabled in each arm.
  3. Execute the ordered 0000, 1100 and 1111 configurations with the two CPU inspections and checked route/resource accounting.
  4. Compare raw generated IDs, Down hashes, stage records and weight-check coverage; retain actual child, inspection, launcher and recovery exit statuses.
  5. Audit the saved evidence before promoting a conclusion. A separate matched timing experiment would be needed for a speed claim.

This article documents relative conditions and recorded outcomes. The exact frozen runtime bundle and input/intermediate tensors are not provided as public reproduction artifacts here, so it is not a self-contained runnable benchmark. No command line or raw tensor dataset is invented to fill that gap.

Boundaries and next decision

Only the three listed GPU configurations were executed in this group. CPU routing proofs covering 16 bit combinations do not establish numerical correctness for all 16 combinations. The independent saved-only audit returned CPU exit code 0, rehashed 167 sealed evidence artifacts, checked 99 harness pins and 1,107 core pins, and independently confirmed all five command/exit joins (final seal: ea89898c). This audit verifies saved evidence and its accounting; it did not independently recheck raw tensors. No candidate promotion, generalized parity, request speedup or new native/vLLM ratio is concluded here.

The next engineering decision is based on the audited correctness evidence and cumulative material improvements. Whole-model timing is not an automatic next step. Related background: QKVZ-only native accuracy and the measurement contract.
