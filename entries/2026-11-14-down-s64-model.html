2026-11-14 / runtime experiment E10 · down-only S64 integration

One kernel substituted.
A measured model-request improvement.

Replacing only the current decode down-projection export with qualified S64 reduced the native request median from 4,873.035 to 4,561.371 ms in one OFF/ON/ON/OFF experiment: about 312 ms, or 6.40%. This is an integrated native A/B, not a fresh vLLM comparison.

The baseline here is the actual current decode-down CUBIN, b360e188, not the experimental C64 control from the standalone descriptor study. Standalone C64/S64 gains cannot be carried over as predicted model gains.

Only this numerical CUBIN changes; the other 70 stay fixed.

The experiment uses the same clean binary at source identifier 98d81a97, with -O3 and no NDEBUG. Source-to-link provenance was audited; the 20 plus 1,032 recorded pins matched. OFF uses the current manual-K16 export; ON uses the natural full-tile S64 export. Unlike the earlier same-source C64/S64 study, this integration changes both implementation form and descriptor specialization, so it is not descriptor-only causal evidence. It changes the selected export at the decode down-projection boundary, not the entire MLP, prefill, activation path or runtime allocation policy. Scratch pooling is OFF in both arms.

Exact supported dispatch contract

The supported operation is BF16 Y = A × Wᵀ, M=32, N=2,560, K=9,216, with FP32 accumulation and the qualified BF16 round-to-nearest output contract described in the descriptor evidence.

Actual viewShapeStrides, in elementsAddress requirement
A[32, 9216](9216, 1)16-byte aligned
W[2560, 9216](9216, 1)16-byte aligned
Y[32, 2560](2560, 1)16-byte aligned
# Dispatch contract, explanatory pseudocode
for view in (A, W, Y):
    require live_owner(view)
    require exact_expected_extent_shape_and_stride(view)
    require (owner_payload(view) + byte_offset(view)) % 16 == 0
# Reject on mismatch; no override and no fallback in this path.
launch(selected_decode_down_export, checked_views)

The checks cover the live view, not merely its allocation base. Invalid extents, strides or addresses must not reach the specialized launch. Checked rejection is part of qualification; no general fallback or safety override is claimed.

Validation is separate from the timed path

A separate untimed validation ran six requests: 3,072 generated IDs and 2,048 per-layer hashes matched. ON recorded 1,440 specialized calls in that validation scope. The actual resource gates and rejection behavior were checked.

The performance run checked 32 × 512 = 16,384 IDs exactly. Each ON performance process recorded 3,840 specialized calls. These are process totals, not per-request counts. Full diagnostic/hash work from the separate validation was excluded from the timed path.

Pooled OFF: 4,873.035 ms. Pooled ON: 4,561.371 ms. The unrounded pooled medians are 4,873.0348855 ms and 4,561.370957 ms: a reduction of 311.6639285 ms (6.395684%), or 1.0683268× speedup in this experiment. All four children, the launcher and independent recovery actually exited 0, without retry.

The adjacent-block reductions were 5.8392% and 6.6560%; same-arm median drift was +0.5487% for OFF and −0.3235% for ON. Every observed ON sample was below every observed OFF sample in this one run. That separation does not establish a distribution-wide guarantee or statistical confidence level.

The table contains block summaries; the CSV and JSON also provide chronological timed samples transcribed from the sealed report. Bounds are observed minima/maxima, not confidence intervals.

Each child recorded 75,272 launches, 71 plans and 65 modules. Unchanged counts included 83,032 logical retirements, 86,352 retirement synchronizations, 4,233 batch APIs and 3,364,326 logical guards covering 107,658,432 bytes. Resident weights comprised 330 owners totaling 8,411,504,128 bytes, with zero generation weight I/O.

The S64 sm89 resource record reports 134 registers, 94,208 shared-memory bytes, maximum dynamic shared memory 7,168 bytes and requested dynamic shared memory 0. No override was applied; these are resource/launch facts, not dynamic-utilization measurements.

Measured significance and limits

This is evidence that the qualified one-kernel substitution improves the measured native model request under these conditions. It does not establish how every layer, batch size, prompt length, precision or GPU will behave. A single ABBA run still has thermal and desktop-GUI interference limits.

No new compiler-resource attribution is inferred from the model time. The earlier descriptor study supplies static-code and standalone evidence; this experiment tests integration and request-level effect. Pooling remains OFF, so neither its correctness nor its performance is folded into this gain.

vLLM was not rerun. The historical native/vLLM gap is a different checkpoint and must not be recomputed by dividing this fresh native median by an old vLLM time. The next cross-runtime claim requires a new matched checkpoint.
