we actually measure?

Package provenance, native compiler flags, JIT options and runtime dispatch are different kinds of evidence. This audit separates them before the next performance comparison.

No new performance ratio. This is a build/runtime evidence audit, not a new model benchmark. It strengthens the description of the reference without proving every historical shared object's exact compiler flags or mapping every cached JIT kernel to a timed request.

The historical V2 benchmark configuration

  • enforce_eager=False.
  • Compile mode 3 means VLLM_COMPILE, not C++ compiler -O3.
  • Inductor compilation and actual FULL_AND_PIECEWISE CUDA Graph configuration/capture were recorded.
  • FA2 attention and Triton/FLA prefill paths were identified. This does not mean every layer uses one backend.
  • Sampler, environment and cache settings were explicit in the original evidence; a reproduction must pin their values rather than rely on defaults.
  • Two recorded runs had 235 versus 300 KV blocks. They must not be described as having identical VRAM reservation.
  • One compilation path took 16.80 s and an AOT-related startup path 0.31 s. These are preparation observations outside the request timer, not inference-speed measurements.

Runtime compile/graph choices are described in v0.32.0 compilation configuration and the CUDA Graph dispatcher. Actual recorded configuration remains necessary: source capability alone does not prove that a particular request took that path.

What the graph trace does and does not show

A separate historical trace used a 17-step workload with log_stats enabled and observed 15 actual CUDA Graph launches per request. It is not the newest fixed-workload per-step trace and cannot be silently substituted for it. Capture/configuration records and observed replay events answer related but distinct questions.

A JIT “debug” key is not a Debug host build

The audited JIT cache contained 190 metadata records: 39 with debug=True and 151 with debug=False. The true values commonly corresponded to Inductor's assert_indirect_indexing behavior. They do not establish a C++ Debug or -O0 build.

Not every cached entry was mapped to kernels launched inside timed requests. Therefore neither the number of debug-marked records nor the cache's presence quantifies benchmark overhead. Do not arbitrarily disable these checks to make the reference faster: first identify the exact timed kernel and the assertion's semantic role.

Preflight for the next paired comparison

  1. Pin public wheel filename, distribution URL and SHA256, plus runtime version/CUDA suffix and relevant extension RECORD checks. Preserve exact build receipts where available; explicitly mark missing historical ones.
  2. Pin model revision, checkpoint/input hashes, dtype, batch, prompt IDs, generation/EOS and sampler settings.
  3. Capture effective compile backend/mode, graph mode and actual request dispatch. Record relevant environment, cache/prefix-cache choices and any AOT reuse.
  4. Record actual KV block count, memory reservation and free memory after preparation. Do not infer equal memory policy from equal model and batch size.
  5. For a separate diagnostic trace, map launches to generated code/cache identities and mark collection gaps. Never use profiled elapsed time as the primary unprofiled benchmark.
  6. Keep prepare/compile/capture/warmup costs outside the stated request timer, while reporting them separately. Include the same request setup, output and cleanup boundaries in both engines.
  7. Preserve raw samples, actual exits/recovery, expected-versus-actual IDs and the exact executable/configuration pins together.

A field checklist is available as JSON. It is a template with unfilled fields, not a validated new run or executable command. Exact historical command values and full receipts must be recovered from the evidence bundle before replay.

Scope of the conclusion

The package and runtime evidence is consistent with the optimized vLLM execution description used in the log. The audit does not turn a default build setting into proof of every historical compiler flag, does not attribute the native/vLLM gap to a single feature, and does not report a fresh timing. See the native host-build correction and separate native host-only -O3 result.
